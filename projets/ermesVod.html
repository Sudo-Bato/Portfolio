1. Contexte & Problématique

L'entreprise souhaitait s'affranchir des plateformes tierces comme Patreon pour proposer ses formations et séances d'hypnose. Le défi était technique et économique : comment héberger et diffuser des centaines de vidéos lourdes de manière sécurisée sans exploser les coûts d'infrastructure ?

Solution retenue : Migration d'un hébergement mutualisé vers un VPS Linux maître, permettant l'installation d'une stack personnalisée (Node.js/FFmpeg) pour un coût fixe (~5€/mois).

2. Architecture Technique

J'ai conçu une architecture de micro-services conteneurisée avec Docker pour garantir la portabilité entre le développement (macOS) et la production (Ubuntu VPS).

🖥️ Frontend (Vue.js 3)

SPA réactive avec Vue Router. Intègre hls.js pour lire les flux vidéos sur tous les navigateurs.

⚙️ Backend (Node.js)

API Express gérant l'auth (JWT), le transcodage (FFmpeg) et la distribution des fichiers statiques.

🔐 Sécurité

Reverse Proxy Caddy (SSL Auto), Fail2Ban pour le SSH, et RBAC (Role-Based Access Control) pour l'API.

💾 Stockage & BDD

MySQL 8 pour les données utilisateurs. Volume Docker partagé pour les Teraoctets de vidéos.

4. DevOps : Enjeux de Production

Le passage du développement local (Docker Mac) au VPS de production (Linux) a nécessité de résoudre plusieurs défis critiques :

Problème CORS & Mixed Content

Le reverse proxy SSL (HTTPS) bloquait les appels vers l'API interne configurée en HTTP.
Fix : Reconstruction de l'image Docker frontend avec les variables d'environnement de production pointant vers le domaine sécurisé.

Persistance des Volumes

Le conteneur Docker ne "voyait" pas les fichiers uploadés via SFTP.
Fix : Correction du mapping des volumes dans docker-compose.yml pour lier le dossier /home/user/videos de l'hôte au dossier /app/raw du conteneur.

Routing SPA (Nginx)

Rafraîchir la page renvoyait une erreur 404 Nginx.
Fix : Ajout de la directive try_files $uri $uri/ /index.html; pour laisser Vue Router gérer l'URL.
